# 2026 300场候选池：独立来源核验流程

状态：已实现自动核验审计脚本；是否通过以每次 Actions 实际产出的核验报告为准。当前不代表已有比赛核验通过或300场样本已冻结。

## 当前流程
1. `collect_2026_300_sample_candidates.py` 从各联赛候选来源采集日期、联赛、主客队和完场比分。
2. `verify_2026_300_sample_independent.py` 使用独立的 SofaScore 赛果数据，对候选记录逐场交叉核对。
3. 核对候选日期及前后各一天，降低 UTC 与联赛当地日期跨日造成的漏匹配风险。
4. 必须同时匹配联赛、主队、客队、完赛状态和90分钟/常规完场比分，才标记 `verified`。
5. 其他状态均不得自动修正或计入冻结样本。比分冲突、身份歧义、未找到、数据源不可用、比赛未完赛均保留审计记录供人工核查。
6. 报告输出为 `independent_source_verification.csv` 和 `independent_source_verification_summary.json`，通过 GitHub Actions artifact 留存90天。

## 结果状态
- `verified`: 日期容差内找到唯一比赛，联赛/主客队/完场比分全部吻合。
- `score_conflict`: 找到唯一的联赛和主客队候选，但比分不一致。
- `ambiguous_secondary_match`: 找到多场相似候选，不能自动判定。
- `secondary_not_finished_or_score_missing`: 身份候选存在，但来源未提供可用完场比分。
- `not_found_secondary`: 独立来源没有匹配记录。
- `secondary_lookup_incomplete`: 独立来源请求出现错误，不能将“未找到”解释为比赛不存在。

## 韩国 K League 1、日本 J1 优先规则
- 优先检查韩文/日文队名与独立来源英文队名的别名映射。
- 别名或联赛名称无法唯一对应时必须保留未核验状态，不允许只凭日期和比分相同就判定通过。
- J1 特殊赛季若来源赛事名称不明确，也必须人工复核后才能认定为目标联赛。
- 独立提供方无法返回相应比赛时，不用同一官方站点的另一页面冒充独立来源。

## 冻结闸门
当前脚本将 `eligible_for_freeze_rows` 固定为 0，自动核验不会冻结300场样本。只有完成来源冲突复核、唯一比赛键检查、七联赛覆盖检查、人工抽查及单独批准后，才能建立冻结文件。未核验完成前禁止训练/回测，V5.1 与历史预测保持不变。
