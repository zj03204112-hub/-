# V5.1 赛后复盘归档标准（长期规则）

本标准适用于今后所有足球赛后复盘，包括五大联赛、韩职、日职、欧国联及其他已纳入跟踪范围的赛事。每次复盘都应在仓库保存逐场记录；不允许只写赛果与预测比分而省略数据质量说明。

## 1. 每场比赛必须记录的基础字段

- 比赛日期（北京时间）、赛事/联赛、主队、客队、比赛状态。
- 实际全场比分、半场比分、90 分钟胜平负。
- 赛前原始预测是否存在；若存在，记录文件/记录 ID、冻结时间及原始内容。
- 若原始预测缺失，必须标记为“回顾性重建”，不得冒充赛前预测或计入正式赛前命中率。
- V5/V5.1 版本、策略编号、预测时间，以及预测是否处于开赛前 6–12 小时窗口。

## 2. 伤停、首发和球员信息

每场必须核查并记录：
- 伤病、停赛、出战存疑球员，信息来源与采集时间。
- 官方首发、替补席、临场阵容变化；若赛前尚未公布，标记“未公布/待核实”。
- 关键球员近期出场时间、进球、助攻、射门/创造机会，以及可获取的防守贡献数据。
- 关键缺阵对进攻、防守和定位球的可能影响；说明判断依据，不得只写“有伤停影响”。
- 数据状态分别标记为“已采集”“已核实”“已进入模型计算”。采集到不代表模型已使用。

## 3. 进攻、防守与 xG

每场应尽量保存赛前可用数据：
- 主队和客队赛季 xG、xGA，以及主客场拆分。
- 近期进攻效率、防守效率、近 3 场结果与可用的射门/机会质量数据。
- 模型内部主队预期进球 λ_home、客队预期进球 λ_away，及其输入来源、生成时间和版本。
- 如有数据，记录赛后实际 xG 作为诊断字段，但必须与赛前 xG/λ 分开存放，禁止将赛后数据当作赛前输入。
- 若数据源未提供、覆盖不完整或口径不一致，明确记录缺失原因；不得编造 xG 数值或把估算值标成供应商实测值。

## 4. 其他赛前因素

每场检查并记录可获取的：
- 战术与对位、主客场实力、球员近期状态。
- 天气、场地、裁判信息。
- 盘口及变化（含竞彩让球数、采集时间和来源）；盘口只能作为辅助信息，不能单独决定胜负。
- 赛程密度、休息天数、下一场对手强度/重要性、潜在轮换和战意。
- 专业足球评论员分析或可信公开预览，并注明来源及其只是辅助判断。

## 5. 预测输出与赛后核验

逐场保留：
- 第一比分、第二比分。
- 90 分钟胜平负。
- 竞彩让球数、让球胜平负、穿盘风险。
- 半全场、风险说明、置信度、策略编号。
- 实际比分、实际胜平负、实际让球结果、命中/未命中/无法核验。
- 第一比分与第二比分的精确命中分别统计；胜平负与比分准确率不得混为一项。

### 让球结算硬规则

- 90 分钟胜平负与竞彩让球胜平负独立核算。
- 让球胜平负只由**第一比分**和已核实的赛前竞彩让球数机械计算。
- 第二比分绝不参与让球结果计算。
- 若赛前盘口缺失或无法确认，让球结果标记“待核实”，不得猜盘口、倒推盘口或强行结算。

## 6. 复盘诊断与模型校准

每轮复盘应包括：
- 按联赛和比赛列出数据完整性，标记缺失字段及来源。
- 诊断 90 分钟胜平负混淆、平局漏判、主客场偏差、λ 误差、净胜球 0/1/2/3+ 分布、第一/第二比分表现、高置信度错误。
- 检查伤停、首发、关键球员、xG/λ、战术、赛程因素是否真的进入模型计算；若没有，写明“未进入模型”，不可把它们描述为模型已使用。
- 给出后续实验建议，但不能只凭少量比赛直接修改生产参数。一次只改一个模块，保留旧版基线，使用独立时间留出集验证。
- Nations League 验证集继续独立统计，不与五大联赛固定样本混合。

## 7. 归档和数据质量

- 每个比赛日保存一份 Markdown 复盘报告，必要时附 CSV/JSON 逐场明细。
- 同步更新索引或 README，便于按日期、联赛、模型版本查询。
- 明确记录数据源 URL、抓取/核验时间、数据状态及模型是否实际使用。
- 对来源冲突、比分未确认、阵容未公布、盘口缺失的场次保留待办，不要静默覆盖。
- 只有在 GitHub 返回成功 commit SHA 后才报告“已写入仓库”；只有在实际运行模型并取得输出后才报告“模型已运行”。
