## 归档链路结论
1. GitHub main 近期存在自动提交：`auto: update current season results`（2026-10-10 02:45:55Z）和 `auto: update 30-match production validation`（2026-10-10 04:04:23Z）。这证明相关文件曾被提交，不代表每场预测都已和实际赛果一一匹配。
2. `data/validation_report.json` 报告 8,548 场历史比赛，`data/model_comparison_30.json` 报告 8,740 场；预测快照唯一比赛数同样为 8,548。三者存在覆盖口径差异，必须先按 match_id 对账，不能把 8,740 场模型回测当作 8,740 场均有原始赛前预测归档。
3. 数据库 review 只有 6 行；仓库虽有逐日复盘提交，但数据库与文件归档是否完全同步尚未证明。
4. xG、伤停、球员聚合特征当前覆盖不足；当前 `compare_models.py` 的胜平负主计算路径没有直接读取 `team_features`、`injuries`、`player_match_stats` 或 `player_features`。不能宣称这些特征已提高准确率。
5. V5.2 阵容投影必须通过 `data_cutoff <= kickoff - 12h` 和可信来源状态检查；未能证明时间与来源的记录应按缺失处理。
