# 每日竞彩足球预测自动工作流规则

> 适用范围：用户提出“预测比赛”“预测今日比赛”“预测明天比赛”等请求时的赛前流程。默认以北京时间（Asia/Shanghai）确定竞彩日期。本文是工作流规范，不代表 GitHub Actions 能读取 ChatGPT 对话；聊天请求触发仍由助手执行。

## 触发与交付原则

1. 用户提出预测请求时，先自动搜索当日中国体育彩票竞彩足球全部场次，再开始逐场预测。
2. 一次性完成检索、交叉核验与计算后统一交付；不要先发不完整的分批结果。
3. 不把已开赛或已完赛场次混入赛前预测。已开赛/完赛场次单列状态；仅预测尚未开赛场次。
4. 不用猜测填补数据。无法可靠确认的字段应明确说明来源限制，但最终报告不要用“待核实”作为占位答案来掩盖检索不足；继续检索可靠来源，只有确实无法获得时才报告“公开来源未能确认”。

## A. 赛程与比赛身份

对每一场核对并保存：
- 竞彩官方编号、赛事名称/赛事级别、主队、客队；
- 官方开球时间与时区（统一展示北京时间）；
- 赛事状态：未开赛、进行中、完赛、延期/中止/取消；
- 竞彩官方赛程来源、联赛/赛事官方赛程来源、核验时间；
- 队名别名映射和冲突处理结果。

竞彩列表与联赛官方赛程必须交叉匹配。编号、队名、赛事级别、开球时间有冲突时，继续查证，不能强行匹配或凭旧赛季印象判断赛事级别。

## B. 赔率快照（不等待停售）

- 在本次预测时点获取并记录官方竞彩可见的胜平负赔率、官方让球数和让球胜平负赔率。
- 保存抓取时间、页面/接口来源、原始赔率值与数据状态。
- 本次预测赔率是不可变快照；后续赔率变化新增快照，不覆盖本次预测记录。
- 不必等停售。若本次预测时点页面不可访问或没有展示值，继续搜索官方公开来源；仍无法确认时说明原因，不可用其他公司的赔率冒充官方竞彩赔率。
- 区分“预测时点赔率”和“停售赔率”；本流程默认使用预测时点快照，不要求等待停售。

## C. 正式首发、伤停、近期状态

### 首发与伤停
- 首发只在俱乐部、联赛/赛事官方比赛中心或可靠比赛中心已发布正式首发名单后标为“正式首发已确认”。
- 未发布正式首发时，明确标注“官方首发尚未发布”，不得把媒体预测阵容写成正式首发。
- 伤停按球员逐项记录：球员、球队、状态（确定缺阵/停赛/出战存疑/已恢复/未发现可靠报道）、信息日期、来源链接。
- “未发现可靠报道”不等于“全员健康”；不得将没有信息写成确认无人伤停。

### 最近5场正式比赛
- 主客队分别整理最近5场正式比赛：日期、赛事、对手、主/客、比分、胜/平/负、进球、失球。
- 排除友谊赛；如用户对杯赛、洲际赛有排除要求，按其约束执行。
- 计算近5场战绩、进失球合计/场均、零封数；主客场分项可获得时一并展示。
- 使用可靠赛果来源并保存来源与核验时间。赛果状态未结束或比分未确认的比赛不计入近5场完成样本。

## D. 赛前分析与预测输出

每场必须给出：
1. 90分钟胜/平/负（独立于让球结果）；
2. 第一比分、第二比分（按模型概率排序，二者不可互相替代）；
3. 半场/全场结果；
4. 置信度（明确它是模型概率、校准概率还是主观等级，不混用）；
5. 风险说明（平局、阵容不确定、疲劳/赛程、战术对位、进球分布尾部等）；
6. 策略编号/模型版本（若该版本实际执行并可追溯）；
7. 关键输入证据：实力与近况、首发/伤停、战术、xG/xGA、球员状态、天气、裁判、新闻、赛程与战意。每个字段注明数据来源或缺失原因，不得声称未接入的数据已经进入模型。

不允许仅凭赔率决定胜负；赔率用于记录和风险交叉检查，不取代球队实力、阵容、状态和进球模型。

## E. 官方竞彩让球胜平负的独立计算（硬规则）

- 只使用已核实的官方竞彩主队让球数及第一比分。
- 90分钟胜平负与竞彩让球胜平负分别输出、分别统计。
- 机械计算：将官方让球数加到主队第一比分后，再比较调整后的主客队进球数，得出让胜/让平/让负。
- 第二比分绝不参与让球结算，也不能用90分钟胜平负直接推导让球结果。
- 盘口数值方向必须明确（主队让球为负数，主队受让为正数），展示计算后的调整比分，供用户检查。
- 官方让球数未从可靠竞彩来源确认时，不生成猜测的让球结论；继续检索，确实无法取得时说明限制。

## F. 一次性完整性检查

最终输出前逐场检查以下字段：
- 竞彩编号、赛事级别、主客队、北京时间和状态；
- 预测时点胜平负赔率、官方让球数、让球赔率、采集时间；
- 正式首发状态、伤停证据；
- 主客队最近5场正式赛果；
- 90分钟胜平负、第一/第二比分、半全场、置信度、风险；
- 第一比分 + 官方让球数 -> 机械计算的让球胜平负；
- 证据链接、模型版本、预测时间。

先完成所有可用来源的交叉核验，再一次性输出完整清单。若部分公开数据确实无法取得，列出明确缺失字段、已尝试来源和原因；不得虚构数据、声称全部完成或用占位符替代检索。

## G. 快照、归档与赛后复盘

- 保存不可变的赛前预测快照：比赛唯一标识、竞彩编号、预测时间、赔率快照、来源、模型版本、预测字段。
- 赛后追加实际结果和复盘，不覆盖赛前预测与赔率快照。
- 取消、中止、未结束或终场比分未确认的比赛不计入准确率分母，单独列出。
- 90分钟胜平负、比分1、比分2、半全场、竞彩让球结果分别核验。
- 任何正式模型准确率或版本对比必须使用可追溯原始预测与固定独立样本；不得将对话中的手工判断冒称为模型正式运行结果。

## 重要的执行边界

本文件把助手的预测流程规则化。GitHub Actions 无法自动感知用户在 ChatGPT 中发送的自然语言请求；除非另外实现数据采集脚本并由工作流触发，否则不能声称本文件本身已经启用实时自动抓取、首发监控或预测写库。
