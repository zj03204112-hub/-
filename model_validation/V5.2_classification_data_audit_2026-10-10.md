# V5.2 诊断阶段 1：胜平负分类与特征接入审计

日期：2026-10-10  
分支：feature/v5.2-classification-data-audit  
状态：静态代码审计已完成；真实数据库覆盖率和模型实验尚未运行。  
兼容要求：main 上 V5.1 和所有历史预测不修改、不覆盖。本分支仅用于 V5.2 实验。

## 已确认的代码结论

### 1. 胜平负分类基线
`data_pipeline/compare_models.py` 使用历史进球率、对手强度、Poisson/Dixon-Coles 分布；包含 V3/V4 对照、时间顺序留出、温度校准及 draw-logit bias 实验。H/D/A 概率由预期进球 λ 推导。需要重点核验平局召回率和 H/D/A 混淆矩阵，不能只看总准确率。

### 2. 发现一个必须先排除的时间泄漏风险
`model_lambdas()` 按开赛前 12 小时生成 cutoff，但查询 `lineup_projection` 时只按 `match_id + team_side` 读取 `attack_delta/defense_delta`，没有在 SQL 中限制 `data_cutoff <= cutoff`，也没有检查 `source_status`。如果同一比赛的阵容投影表存在赛后更新或开赛后记录，历史回测可能读取到未来信息。当前这只是代码层面的泄漏风险，尚未证明数据库里确实有受影响的行；必须先审计并修正读取规则，再把结果用于评估。

### 3. xG/xGA
`team_features` 表有 `xg_for/xg_against` 字段，但当前检查到的 `model_lambdas()` 路径没有读取这些字段。因此不能认定球队 xG/xGA 已进入胜平负计算。

### 4. 球员数据
`player_match_stats` 有球员 xG/xA、射门、关键传球、抢断、拦截等字段；`player_features` 有 `attack90/defense90/influence90/start_prob` 等字段。但当前 `model_lambdas()` 没有直接读取这两张表。

### 5. 发现的数据质量问题
`data_pipeline/collect_api_football_player_data.py` 把 API-Football 球员 xG/xA 写成硬编码 `0.0, 0.0`。这会把“缺失/未解析”误当成真实的零值。V5.2 必须将缺失保留为 NULL 或独立可用性标记，不能伪装成观测值。修复前，不应把这些字段当成真实球员 xG/xA 用于建模。

### 6. 伤停数据
`injuries` 表有可出场概率、预计首发概率、进攻/防守影响和时间截点；`analyze_draw_causes.py` 读取它们做赛后原因分析。但赛后原因分析不等于预测引擎使用数据。当前预测路径只会通过 `lineup_projection` 聚合攻防 delta 间接使用阵容影响；覆盖率、来源状态及 T-12h 合规性需要真实数据库审计。

## 后续执行顺序（不可跳步）

1. **数据库只读审计**：统计各表总行数、有效行数、比赛覆盖率、来源状态、xG/xA 的 NULL 与零值、T-12h 截点合规性；保留原始数据库不变。
2. **先堵住时间泄漏**：让 lineup projection 查询只接纳开赛前 12 小时及之前、来源状态有效的记录；如果 schema 无法证明时间与来源，则该场特征按缺失处理，不默认使用。
3. **修复球员采集语义**：xG/xA 没有从来源实际解析到时写 NULL/不可用状态，不再写 0.0。保留已有记录和 V5.1，不覆盖历史预测。
4. **冻结独立时间样本**：只用比赛开赛前可获得的数据预测；训练/校准集与最终评估集按时间切分，不能在评估集上选参数。
5. **逐模块消融**：同一批样本比较基线、仅 xG/xGA、仅伤停/首发、仅球员攻防特征、组合模型；一次只加一个模块，再决定是否保留。
6. **分类评估**：报告 H/D/A 混淆矩阵、总准确率、平局召回率、各类别 precision/recall、Brier、Log Loss、置信度分桶，以及净胜球 0/1/2/3+ 分层结果。
7. **验收门槛**：不按单日 6–8 场调参；至少积累连续独立样本并与基线比较。用户设定的日常 80% 是目标，不代表模型当前已经达标。新版本未稳定优于基线前，不替换 V5.1。

## 真实数据库运行后必须填写的指标

- injuries：总记录数、有效 T-12h 记录数、覆盖比赛数。
- player_match_stats：球员行数、覆盖比赛数、真实 xG/xA 非缺失率、硬编码零值风险。
- player_features：覆盖比赛数、有效球员数、时间截点合规率。
- team_features：xG/xGA 非缺失覆盖率、零值与缺失的区分。
- lineup_projection：覆盖比赛数、来源状态、非零攻防 delta 覆盖率、晚于 T-12h 的行数。
- V5.1 与 V5.2：同一独立时间留出集上的 H/D/A 指标和概率评分。

上述数字目前不能从静态代码检查推断。审计脚本需在实际数据库所在环境运行；未取得审计 JSON 前，不报告虚构覆盖率或准确率。
