# V5.2 诊断阶段 1：胜平负分类与特征接入审计

日期：2026-10-10
分支：feature/v5.2-classification-data-audit
状态：代码静态审计完成；数据库覆盖率与新实验运行结果待工作流真实执行后补齐。
兼容要求：main 上 V5.1 和所有历史预测不修改、不覆盖。本分支仅为新版本实验。

## 1. 主要结论（基于当前仓库代码，不是数据库实测）

### 胜平负分类
' data_pipeline/compare_models.py ' 当前使用历史进球率、对手强度、赛程意图、Poisson/Dixon-Coles 分布，并具备 V3/V4 对照、时间顺序留出、温度校准和 draw-logit bias 实验函数。' model_lambdas() ' 会读取 ' lineup_projection.attack_delta/defense_delta '，但只读取这张聚合表，不直接读取 ' injuries ' 或 ' player_features '。

风险：
- 当前分类基于进球率推导 λ，不能把存在数据库列当作数据已进入模型。
- 平局校准函数存在，但不能只在全量样本上拟合后再报告同一批样本成绩；应只在较早的训练窗口拟合，在后续时间窗口验收。
- 每日 6–8 场的单日结果波动很大，必须保留所有预先冻结的预测，使用滚动样本衡量改进。
- 应记录 H/D/A 概率和混淆矩阵，重点检查平局漏判、主客队错判、不同实力差分层，以及净胜球 0/1/2/3+ 的误差。

### xG / xGA
' team_features ' 表有 ' xg_for/xg_against ' 字段，但在当前已检查的 ' model_lambdas() ' 路径中，λ 由历史进球率和对手调整产生，没有读取 ' team_features.xg_for/xg_against '。因此目前不能认定球队 xG/xGA 已接入胜平负计算。

### 球员数据
' player_match_stats ' 表有球员 xG/xA、射门、关键传球、抢断、拦截等字段；' player_features ' 有 attack90/defense90/influence90/start_prob 等字段。但是当前 ' model_lambdas() ' 没有直接查询 ' player_match_stats ' 或 ' player_features '，所以不能认定这些球员字段已直接进入分类计算。

### 一个明确的数据质量问题
' data_pipeline/collect_api_football_player_data.py ' 将 API-Football 球员 xG/xA 写为硬编码 ' 0.0, 0.0 '。这把“数据源没有提供/代码没有解析”与“球员真实 xG/xA 为 0”混在一起，会污染后续统计。新版本应增加可用性标记，并在来源确实没有值时标记缺失，不应把硬编码零当成观测值。

### 伤停数据
' injuries ' 表保存状态、可出场概率、预计首发概率、进攻/防守影响和时间截点；' analyze_draw_causes.py ' 会读取这些字段做事后原因分析。但是原因分析读取数据不等于预测引擎使用数据。当前 ' model_lambdas() ' 未直接查询 ' injuries '。只有被转换并写入 ' lineup_projection ' 的聚合攻防 delta 才会进入 λ；必须用运行日志验证这条转换是否发生、数据是否在 T-12h 截点前有效。

## 2. 本阶段处理原则

1. V5.1 主分支、固定验证集和历史预测全部保持原样。
2. 所有代码修改仅在本分支进行，版本命名 V5.2-experimental。
3. 先修正数据可用性/缺失标记和接入覆盖率审计，再进行模型实验。
4. 做四组同场、时间顺序比较：
   - Baseline：原 V5.1/V4 分类输出。
   - +xG/xGA：只加入赛前球队 xG/xGA。
   - +player availability：只加入有来源、在 T-12h 前观测到的伤停/首发影响。
   - +player performance：加入按赛前截止时间聚合的球员攻防贡献。
   - Combined：仅在前述单模块结果通过独立时间留出集后才测试组合。
5. 不允许将赛后球员表现、赛后 xG、最终首发或红牌等事件泄漏到赛前特征。
6. 不根据单日 6–8 场调参；先做连续时间切分，报告样本量、H/D/A 混淆矩阵、准确率、Brier、Log Loss、平局召回率和置信度分桶。
7. 只有新版本在独立留出集优于基线且概率校准没有恶化，才考虑晋级；否则保留实验分支，不替换 V5.1。

## 3. 尚待运行时确认的指标

当前没有随仓库检索到可直接读取的实际 SQLite 数据库文件和这次运行的 summary.json，因此下列项目不能伪报数字：
- injuries 的记录数、具有有效 T-12h 数据的比赛数。
- player_match_stats 的球员行数、覆盖比赛数、真实 xG/xA 可用率。
- player_features 的有效覆盖率与时间截点合规率。
- team_features.xg_for/xg_against 的非缺失覆盖率。
- lineup_projection 的覆盖率、来源状态与非零 delta 覆盖率。
- 新模型与 V5.1 在独立时间留出集上的实际胜平负成绩。

## 4. 验收条件

- 数据质量：分别报告采集、核实、进入模型计算三个状态；禁止只报告“有表/有列”。
- 模型质量：至少 100 场连续、时间顺序、预测冻结的独立前瞻/留出样本；与基线同场对照。
- 历史：不得覆盖任何既有预测；回顾性重建场次不进入正式赛前命中率。
- 让球：90 分钟 H/D/A 与竞彩让球 H/D/A 独立核算；让球只用第一比分和真实赛前盘口计算，第二比分不参与。
