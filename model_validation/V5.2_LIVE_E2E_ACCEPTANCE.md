# V5.2 live prediction trace — acceptance status

This remains an isolated integration path. It does not change V5.2 formulas, parameters, V5.1, or the default branch.

## Implemented on the isolated feature branch
- `data_pipeline/run_v52_live_prediction.py`: calls the existing V5.2 lambda/probability functions and records pre-match predictions plus raw Sporttery/Leisu payloads in an append-only SQLite trace DB. The existing prediction runner still has its older Leisu adapter contract and is not yet switched to the HTML scraper.
- `data_pipeline/leisu_public_web_scraper.py`: fetches the public Leisu finished-match list as HTML, extracts visible `/detail-{id}` links, records retrieval time and source hash, and conservatively parses only explicitly labeled full-time scores. It does not call a Leisu API or bypass access controls.
- `tests/test_leisu_public_web_scraper.py`: offline parser tests for event-ID extraction and conservative score parsing.
- `data_pipeline/finalize_v52_official_results.py`: separate result-ingestion utility that looks up official Sporttery results by stored Sporttery `matchId`, checks home/away identity, and refuses to overwrite existing results.
- `.github/workflows/v52-live-prediction-e2e.yml`: compile/tests/database checks plus a manual-dispatch public-page smoke test; artifacts include the scrape report.

## Current verified status
- GitHub Actions run `38853208221` passed compile, append-only tests, and source database integrity checks, but skipped the live prediction step. It predates the HTML scraper.
- The public Leisu finished-match page is readable through the browser and exposes match detail links and visible result rows. A detail URL example is `https://live.leisu.com/detail-4460455`; the browser fetch of that detail URL returned HTTP 405, so automated detail-page retrieval is not yet proven.
- The new HTML scraper and its tests have been committed, but no new Actions run or real scraped artifact has yet been verified in this report.
- The HTML scraper currently discovers event IDs/URLs, not a verified complete set of home/away, kickoff, odds, and final-score fields. The live V5.2 runner has not yet been switched to consume this adapter. Therefore no true one-match end-to-end match-ID linkage or market capture is claimed.
- No full E2E acceptance is claimed and the draft PR must not be merged/promoted to production.

## Required release gates
1. Run the new public-page smoke test in Actions and inspect its artifact for event IDs/links and raw-page hash.
2. Verify that a detail page can be retrieved with ordinary public HTML access; if blocked, stop and use an accessible public page or authorized data source.
3. Reliably parse home team, away team, kickoff, odds/handicap, and full-time score from visible page content; leave fields unset when ambiguous.
4. Match one real fixture uniquely across the model DB, Sporttery `matchId`, and Leisu page event ID; preserve raw source and retrieval timestamps.
5. Run V5.2 prediction only after identity mapping is unique; after kickoff, match the official score to the same fixture ID and verify the score parser against the source.
6. Test prediction-time-before-kickoff, duplicate/ambiguous IDs, result conflicts, and append-only guarantees. Do not modify V5.1 or historical predictions during validation.
