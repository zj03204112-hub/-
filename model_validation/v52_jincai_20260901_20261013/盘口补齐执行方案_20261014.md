# 448场盘口补齐执行记录（2026-10-14）

## 目标与约束
目标样本：398场 V5.2 DB-native + 50场 Nations League，共448场。保留原始样本、来源标签、match_id，不覆盖 V5.1、main 分支或既有预测。

每场目标字段：fixture_key / native_match_id / source_match_id / Sporttery matchId（可唯一确认时）；kickoff_utc、home、away、league、sample_source；Asian handicap 主队盘口线与水位、客队盘口线与水位；totals 大小球线、Over水位、Under水位；provider、market_name、snapshot_timestamp、snapshot_id/raw_response_hash、source_url。
snapshot_timestamp 必须 <= kickoff - 12 hours，且须能证明时间语义；否则 T-12h 字段标记 MISSING，不得推定。

## 发现的限制
1. 现有合并 CSV 没有逐场可验证的历史亚洲让球/大小球快照字段。
2. Sporttery 公开 getFixedBonusV1.qry / oddsHistory 历史主要是竞彩固定奖金池（例如 had/hhad/ttg），不能直接等同于博彩公司 Asian Handicap 与 Over/Under 的盘口线及双方水位。
3. 现有 validate_sporttery_frozen_500.py 只尝试匹配比赛 ID、读取 hhad 历史；它不提取可验证的 T-12h 时间切片，也不提供完整 Asian Handicap / O-U 市场。
4. 外部历史赔率 API 可以提供按时间点查询的历史快照，但通常需要供应商权限/API key。当前这次工具会话没有可用的外部 HTTP 执行环境或已确认可用的历史赔率 API 凭据，不能声称已成功抓取数据。
5. 公开 CSV 中的收盘赔率可以作为另一个字段集保存，但如果没有历史采集时间/快照证据，不得将其标成 T-12h 数据。

## 采集与验收顺序
1. 固定448场清单，验证448行、唯一比赛键及比赛时间/球队。
2. 对每场尝试官方 Sporttery 赛果/奖金接口，保存原始 JSON、响应 hash、匹配依据及赔率更新时间。
3. 对官方接口不覆盖的 Asian Handicap / totals 市场，使用具有历史快照时间戳的外部赔率供应商；按开球前12小时的快照查询，选择最接近且不晚于 cutoff 的记录。
4. 严格检查球队、比赛日期、盘口类型、线与双方价格；同名/重赛/中立场等歧义不得自动强行匹配。
5. 每场输出 COMPLETE_T_MINUS_12H、PARTIAL_MARKET_ONLY、NO_VERIFIABLE_SNAPSHOT、AMBIGUOUS_FIXTURE 或 FETCH_FAILED。
6. 生成缺失清单和覆盖率报告。只有448/448均具备目标市场及可验证T-12h快照，才宣布“完全补齐”。
7. 原始快照与派生 CSV 一并版本化，校验成功后才允许进入 A—E 校准。
